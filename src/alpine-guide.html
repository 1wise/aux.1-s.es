Versión 3.24.2. Netboot y Standard van a RAM; Extended a disco. Las siete descargas suman 4,51 GB. Los archivos light más sus tar.gz extraídos suman unos 2,98 GB antes de metadatos y temporales. Los modloop conservan su ruta dentro de cada imagen y el repositorio APK corresponde a la misma rama.

Prueba desde cero, sin retirar el despliegue activo

Descomprimir el paquete en una carpeta nueva. Fedora necesita python3, curl, bsdtar, util-linux y links; Debian/Ubuntu: python3, curl, libarchive-tools, util-linux y links. Crear destinos vacíos distintos de producción y comprobar tmpfs:

pth_prueba=/var/www/aux-prueba-5.1.0
pth_ram=/dev/shm/aux-prueba-5.1.0
sudo install -d -m 0755 "$pth_prueba/isos" "$pth_prueba/html" "$pth_ram"
free -h
df -h "$pth_ram" "$pth_prueba"
findmnt -T "$pth_ram"

En Debian sustituir --group nginx por --group www-data:

sudo bash download.sh --only alpine --checksums alpine-SHA256SUMS   --cache "$pth_prueba/isos" --output "$pth_prueba/html" --group nginx --verbose
sudo bash deploy.sh ram --list light --only alpine --checksums alpine-SHA256SUMS   --cache "$pth_prueba/isos" --output "$pth_prueba/html" --ram-dir "$pth_ram" --group nginx --verbose
sudo bash deploy.sh disk --mode mount --list heavy --only alpine --checksums alpine-SHA256SUMS   --cache "$pth_prueba/isos" --output "$pth_prueba/html" --ram-dir "$pth_ram" --group nginx --verbose
sudo bash generate.sh --cache "$pth_prueba/isos" --output "$pth_prueba/html"   --ram-dir "$pth_ram" --group nginx --verbose

El URL PXE de fast-boot.json debe servir ese html de prueba antes de arrancar clientes. En Fedora añadir --mount-context system_u:object_r:httpd_sys_content_t:s0 a los montajes y preparar etiquetas HTTP para el nuevo directorio. No ejecutar chown/chmod sobre las ISO montadas en solo lectura.

Comprobar siete recursos, tres Netboot y cuatro medios Standard/Extended. Para el catálogo completo quitar --only alpine y usar las sumas oficiales de cada distribución. La cuota objetivo sigue en 22 GB RAM y 120 GB disco; --mode extract agrega el contenido extraído a la copia de caché. Tras un reinicio se deben recrear montajes y ejecutar generate.

Correo en equipos reciclados

El Live prepara el sistema; todavía no configura un servidor de correo. Instalar Alpine interactivamente con setup-alpine y usar almacenamiento persistente para colas, buzones y copias. Alpine usa apk, OpenRC y musl; los servicios Fedora/systemd requieren adaptación. La configuración de correo y DNS se realizará después de validar el equipo.
