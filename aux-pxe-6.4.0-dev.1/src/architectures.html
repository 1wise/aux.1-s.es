Arquitecturas: reciclar PCs para IoT

i386 es la etiqueta del catálogo para PC x86 de 32 bits; no implica soporte de un procesador Intel 80386 real. Comprobar CPU, RAM, PAE y requisitos del kernel elegido. No toda CPU de 32 bits soporta todas estas imágenes.

Light: instaladores de red

  • Debian 12.15 i386 netinst para USB/CD y archivo netboot Bookworm para iPXE. Debian 12 es oldstable; Debian 13 no publica un instalador i386.
  • Alpine 3.24.2 Netboot x86, x86_64 y ARM64; Standard x86/x86_64 en light y Extended x86/x86_64 en disco. El generador exige kernel, initramfs y modloop locales antes de ofrecer arranque.
  • Debian estable 13 y Fedora 44 Server netinstall x86_64/ARM64 permanecen en light.

El selector Architecture del menú iPXE permite elegir objetivos compatibles. En BIOS x86 de 64 bits puede ofrecer i386 y x86_64; en UEFI se conserva la restricción del cargador. No cambia el firmware ni emula otra CPU. Los filtros de la web permiten consultar también otras arquitecturas. Las recetas nuevas requieren pruebas reales de arranque.

Cloud: instalador frente a disco virtual

Para instalar una VM desde cero, usar los netinstall estables con hardware virtual compatible. Para importar una VM preinstalada, heavy incluye Debian 13 GenericCloud y Fedora 44 Cloud Base Generic, en amd64/x86_64 y ARM64, formato QCOW2. No se envía un QCOW2 al comando kernel de iPXE.

Importar en el hipervisor correspondiente, configurar CPU/firmware, red y datos cloud-init con clave pública; no publicar credenciales ni una clave privada dentro de la imagen. Los QCOW2 se sirven para descarga, no se montan como ISO. Las URL latest de Debian pueden cambiar: registrar fecha y checksum oficial en cada actualización. El presupuesto de 120 GB debe medirse incluyendo estas cuatro imágenes adicionales.

U-Boot y placas ARM

U-Boot es un cargador de firmware; suele ejecutarse antes del sistema o de iPXE. No existe un U-Boot universal para todas las Raspberry Pi. Las ISO ARM64 existentes requieren una plataforma de arranque compatible; su arquitectura por sí sola no basta.

PlacaConfiguración de referencia U-Boot
Raspberry Pi 3Brpi_3_defconfig
Raspberry Pi 3B+rpi_3_b_plus_defconfig
Raspberry Pi 4Brpi_4_defconfig
Varias Pi ARM64 compatiblesrpi_arm64_defconfig, según documentación

El flujo es firmware de la placa → U-Boot o UEFI compatible → kernel/instalador. Comprobar modelo/revisión, medio SD/eMMC, firmware y device tree antes de compilar o escribir. Esta publicación añade la sección y la documentación: no distribuye un binario U-Boot sin placa identificada ni modifica el firmware del cliente. Pi 1/Zero originales no son ARM64.
